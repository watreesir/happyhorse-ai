# 移动端头部与登录交互改动报告

更新时间：2026-04-14

## 一、本轮目标

本轮只处理移动端头部与抽屉菜单里的登录体验，控制在最小改动范围内，不触碰 SEO、支付、积分发放、生成任务、路由或 metadata。

需求重点：

1. 顶部登录 CTA 文案改为更明确的积分领取表达
2. 移动端右上角补充积分余额显示
3. 移动端抽屉菜单底部增加明确的登录入口
4. 菜单展开后，尝试自动触发现有 Google One Tap / Google 账号选择能力
5. 保持原有导航、主题切换、语言切换和其他配置能力不丢失

## 二、实际完成内容

### 1. 登录 CTA 文案更新

已将未登录 CTA 文案改为、

- 英文：`Sign in to claim 150 daily credits`
- 英文短文案：`Claim 150 daily credits`
- 中文：`登录领取每日 150 积分`
- 中文短文案：`领取每日 150 积分`

说明：

- 完整文案用于主要登录入口
- 短文案用于更紧凑的展示位
- 后续如果你调整“150”这个奖励值，需要同步改这里的文案

### 2. 移动端顶部积分位补充

在移动端头部右侧，已新增紧凑积分胶囊：

- 已登录用户：显示真实积分，并可跳转到积分页
- 游客：显示游客积分余额
- 该展示位位于汉堡菜单左侧，充分利用原本空白空间

### 3. 移动端菜单底部登录入口

移动端抽屉菜单已改成上下两段结构：

- 上半段：导航列表
- 下半段：保留在靠近底部的位置，放置主题切换、语言切换、配置按钮和登录入口

这样可以保持：

- 菜单顶部信息密度不过高
- 登录入口位置稳定，接近你参考图里的交互习惯

### 4. 菜单展开后的 Google 登录尝试

已在移动端菜单专门增加一套登录入口变体：

- 仅在移动端菜单打开时参与渲染
- 对未登录用户，菜单打开后会尝试调用现有 `showOneTap` 能力
- 为避免重复弹出，增加了“单次打开菜单只触发一次”的保护
- 菜单关闭后，再次打开时才允许重新尝试

说明：

- 最终显示成什么样的 Google 账号选择弹窗，仍取决于 Google One Tap 在当前浏览器和设备上的实际策略
- 这部分我没有重写 Google 登录流程，而是复用你当前站点已经存在的登录链路，避免引入新风险

### 5. 兼容现有移动端按钮能力

原来的移动端菜单底部还承载了 `header.buttons` 这类配置按钮。

这次没有移除，而是一起下沉到底部区域，避免：

- 已配置的按钮在移动端消失
- 造成当前配置行为和桌面端不一致

## 四、实现方式说明

### 1. `SignUser` 扩展为两个移动端变体

新增了两个变体：

- `compact-credits`
  - 只负责在移动端顶部显示紧凑积分胶囊
- `mobile-menu-auth`
  - 负责移动端菜单底部登录入口和菜单展开后的 One Tap 尝试

这样做的好处：

- 不需要复制一套新的登录组件
- 原有登录、登出、积分获取、Google 登录、用户菜单逻辑继续复用
- 改动面更小，回归风险更低

### 2. `Header` 改成移动端双区结构

移动端现在分为：

- 顶部条：品牌 + 积分胶囊 + 汉堡按钮
- 抽屉主体：导航列表
- 抽屉底部：主题 / 语言 / 登录入口 / 配置按钮

桌面端结构未重做，只保留原有布局。

## 五、这轮没有改动的内容

以下内容本轮刻意不碰：

- 页面 SEO
- metadata / canonical / JSON-LD
- 路由结构
- 支付逻辑
- 积分发放逻辑
- 视频生成链路
- Studio 页面结构

## 六、验证建议

建议手动验证以下场景：

1. 移动端未登录打开首页：
   - 顶部右侧能看到积分图标与数值
   - 点击汉堡后，底部能看到登录 CTA

2. 移动端未登录展开菜单：
   - 菜单打开后，Google One Tap 会尝试触发
   - 若浏览器允许，应出现 Google 账号选择提示

3. 移动端未登录点击 CTA：
   - 应沿用现有 Google 登录流程

4. 移动端已登录打开菜单：
   - 底部应仍可看到用户相关入口，不影响现有账户菜单

5. 桌面端：
   - 原有头部导航、主题切换、语言切换、登录入口不应被破坏

## 七、后续可选优化

如果后续你还要继续打磨移动端登录体验，可以考虑：

1. 将顶部积分胶囊在游客态增加更明显的提示语
2. 为移动端菜单底部登录区增加更明确的副文案
3. 针对不支持 One Tap 的浏览器，再补一个更显式的 Google 账号选择提示
